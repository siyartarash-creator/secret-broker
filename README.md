# secret-broker

گذرگاه امانت: مدل کلید را **استفاده** می‌کند، ولی هرگز **نمی‌بیند**.

## اصول

1. مقدار کلید فقط با DPAPI ویندوز رمز شده و فقط برای همین کاربر ویندوز قابل خواندن است.
2. مدل فقط نام کلید را می‌داند و قالب `{{secret:name}}` می‌نویسد. مقدار واقعی فقط داخل درخواست خروجی جایگزین می‌شود.
3. هر کلید فهرست میزبان مجاز دارد. میزبان دیگر (حتی شبیه‌سازی‌شده) رد می‌شود.
4. فقط HTTPS. ریدایرکت رد می‌شود (نمی‌شود کلید را به جای دیگری هدایت کرد).
5. اگر مقدار کلید در پاسخ برگردد، با `[REDACTED:name]` جایگزین می‌شود.
6. لاگ فقط نام کلید، میزبان، روش و وضعیت را ثبت می‌کند؛ هرگز مقدار را.

## محدودیت‌ها (صادقانه)

- اگر مدل اجازه‌ی اجرای دستور آزاد (shell) داشته باشد، می‌تواند محیط را بخواند. پس این ابزار را باید **تنها** راه استفاده از کلید قرار داد.
- هر متنی که وارد زمینه‌ی مدل شود (مثلاً کپی‌پیست شما) به ارائه‌دهنده‌ی مدل می‌رسد. کلید را هرگز در چت نچسبانید.
- حذف مقدار از حافظه‌ی پردازش بهترین تلاش است، تضمین امنیتی کامل نیست.

## نصب و استفاده

```powershell
# ۱) ذخیره‌ی یک کلید (ورودی مخفی)
powershell -ExecutionPolicy Bypass -File set-secret.ps1 -Name openrouter

# ۲) تعیین میزبان مجاز
node src/cli.js allow openrouter openrouter.ai "LLM gateway"

# ۳) فهرست (بدون مقدار)
node src/cli.js list

# ۴) تست یک درخواست
node src/cli.js call openrouter https://openrouter.ai/api/v1/models

# ۵) لغو دسترسی یک میزبان / حذف کامل
node src/cli.js revoke openrouter openrouter.ai
node src/cli.js remove openrouter
```

## مسیرها

| چه | کجا |
|---|---|
| کلیدهای رمزشده | `%USERPROFILE%\.ecc\secrets\vault\*.dpapi` |
| سیاست میزبان‌ها | `%USERPROFILE%\.ecc\secrets\policy.json` |
| لاگ بدون مقدار | `%USERPROFILE%\.ecc\secrets\audit.log` |
